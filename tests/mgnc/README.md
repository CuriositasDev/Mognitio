# Experimental compiler verification

Build the compiler with the fixed seed described in compiler/mgnc/README.md.
The regular test suite remains unchanged. These runners exercise the separate
experimental compiler and its internal phases.

## Requirements

Use non-root Linux AMD64 with Python 3, strace, bubblewrap, setfacl, bindfs and
fusermount3. Bindfs is needed for the explicit noexec observation; the runner
accepts --bindfs /path/to/bindfs without modifying the system installation.

## Focused checks

Run foundation.py, frontend.py, parser.py, checker.py, ir.py,
ir-definitions.py, encoding.py and driver-internal.py with --seed SEED.
Check generated width data with generate-width.py --check.

The v1.4 internal source snapshot, string lexer and residual terminal scanner
are checked by shared_lexer.py --seed SEED. The public
parse and build commands use this same snapshot and structural frontend.

The shared chart uses grammar.txt and generated Grammar / GrammarPart modules.
Run generate_grammar.py --check and generate_storage.py --check to verify every
generated source. Chart_internals.py --seed SEED verifies persistent arena updates,
old snapshots, bounds and invalid grammar rejection. Forest_oracle.py compares
all reachable families with an independent bounded CFG oracle using a dump harness;
repeat with reversed prediction order. Structural.py --seed SEED --evidence RESULT.json
builds both probes from the exact Git HEAD. Generated modules remain part of C1.

Run source_profile.py, native.py, workloads.py, driver.py and faults.py with
--compiler COMPILER. Native execution can also compare against the independent
fixed seed using --seed SEED. Tests cover immutable operands, non-completion,
loop control boundaries, UTF-8 startup, primary diagnostics and publication.
Source_profile.py, native.py and workloads.py accept --evidence RESULT.json
for source/artifact hashes and per-case observations. Workloads.py exercises
runtime argument branching and accumulation with the same executable across
empty, spaced, non-ASCII and option-like arguments.

The syscall injector operates on an unchanged compiler executable. It can
replace a successful syscall reply after the side effect, which distinguishes
Unknown publication with an existing artifact from a rejected commit.

Noexec verification uses a private user-owned FUSE bind mount. When that provider
rejects atomic no-replace rename, the runner observes the public failure
separately and verifies that a successful underlying publication remains
non-executable through its noexec alias. It does not label the rejected direct
publication a success or change the output's execute bits.

Review.py adds body-boundary, mixed-comparison and exact diagnostic-location
regressions. Run it with --compiler COMPILER --evidence RESULT.json; it retains
every observation and fails if any expected acceptance, rejection or span differs.

## Frozen resource fixtures

The 21 sources and manifest in fixtures/scale are generated by scale-fixtures.py.
Metadata.py adds observed parser node counts and maximum syntax depth, comparing
the scanner token count with the independent generator count. Runtime results
come from the generator's arithmetic expectations, not the compiler output.

To regenerate before freezing a new acceptance run:

~~~sh
python3 tests/mgnc/scale-fixtures.py --output fixtures-directory
python3 tests/mgnc/metadata.py --seed SEED --fixtures fixtures-directory
~~~

Measure.py requires --compiler, --fixtures and --evidence. Defaults are one
warm-up and five measured compilations per cell. It records monotonic wall time,
wait4 peak RSS for each individual child, all process results, executable hashes,
modes and runtime results. It retains failed samples and uses a 120-second
process timeout. Each cell must have median wall time at most 30 seconds and
maximum measured RSS at most 256 MiB, with every sample correct.

Run formal measurements sequentially in a quiet environment. Record CPU, OS,
kernel, filesystem, governor, limits, swap, load and any external noise before
the run. Do not discard a slow sample without a recorded external cause.

## Isolation

Isolated.py accepts --compiler, repeated --userland base-rootfs directories and
--evidence. Each rootfs needs empty /emitter and /output placeholders and must
contain no old compiler, development toolchain or Python interpreter. It runs
compilation and generated programs separately without source or compiler
access during the latter, and traces the compiler for unexpected process execs.
The rootfs file inventory and OS identity are included in the evidence.

## Version 1.4 parse acceptance

Parse_cases.py covers lexical and structural cases, parse/build boundaries and
review diagnostics. Parse_driver.py checks CLI and read-only behavior;
parse_mutations.py corrupts four complete C0 files; parse_faults.py distinguishes
allocation failure, OS termination and harness timeout. Each accepts --compiler
COMPILER --evidence RESULT.json. Residual_locations.py --seed SEED checks raw
cursor spans. Parse_compatibility.py compares valid normal-toolchain features
outside the experimental profile; put the source-development SBCL on PATH.

Freeze C0 and the exact final C1 with parse_workloads.py --revision COMMIT
--output DIRECTORY. Parse_measure.py --compiler COMPILER --fixtures DIRECTORY
--evidence RESULT.json measures every file and all 35 scale cells. Defaults are
one warm-up and five measured runs; --preflight is explicitly preliminary.
Per-file/cell median is at most 30 seconds, each corpus round median sum at most
120 seconds, and peak RSS at most 512 MiB. The inherited native budget remains
30 seconds / 256 MiB and is measured separately with measure.py.

Parse_isolated.py takes the same compiler and frozen fixtures, repeated --userland
rootfs paths and --evidence RESULT.json. It checks every C0/C1 file in each minimal
userland. The existing isolated.py separately checks native generation and output
execution. Shared host kernels are recorded separately from userland versions.

## Internal growth and completion evidence

Ambiguity.py --seed SEED --compiler COMPILER --evidence NEW_DIRECTORY builds an
instrumented Git HEAD archive and checks 26 positive/negative growth cells.
It retains all type/value alternatives, compares small cells against the independent
CFG oracle, and records items, families, maximum columns, key comparisons and
family deduplication. The same inputs receive one warm-up and five measured runs
with the unchanged public compiler. These supplementary cells do not replace the
formal corpus, parse scale or inherited native matrices.

Review_mutants.py --seed SEED --compiler COMPILER --evidence NEW_DIRECTORY
checks five intentional compiler faults against the unmodified baseline.
Acceptance.py checks the published v1.4 evidence ledger, source identity, case
coverage, complete sample matrices, isolation and compatibility input hashes.
Run python3 tests/mgnc/acceptance.py after generating all completion records.

## Version 1.5 project semantics

Build the candidate with the verified [replacement seed](../../verification/v1.5.0-seed2.md).
Keep that artifact fixed while recording its SHA-256, the complete C1 source
inventory, and the seed receipt. The compiler is experimental; these checks do
not switch the normal toolchain to mgnc.

- v150-input.py, v150-headers.py, v150-types.py, v150-graph.py, v150-int-map.py,
  v150-text.py, v150-layout.py and driver-internal.py take --seed SEED. They check
  internal input, resolution, type, dependency, storage, projection and driver
  invariants independently of public diagnostic formatting.
- v150-conformance.py, v150-boundaries.py, v150-catalog.py, v150-inherited.py,
  v150-review.py and v150-project-faults.py take --compiler A --evidence FILE.
  The versioned adapters retain explicit reasons for changed diagnostic phases.
- v150-semantics.py --compiler A checks complete bodies and non-evaluation.
- v150-review-flow.py --compiler A --evidence FILE checks unique Unknown operator
  selection, ambiguous alternatives, module initializer reachability, compile-time
  declarations, ordinary-call locality, and unused modules. Native successes are
  executed; rejected builds must preserve an existing output.
- classification_order.py --seed SEED --force-full-classification --evidence FILE
  reverses grammar prediction and forces the full classification path.
- v150-coverage.py --seed SEED --corpus C0 --evidence FILE compares all modules,
  declarations and completed bodies against an independent source scanner.
  Repeat for C1. Its instrumented binary is not the production candidate.
- v150-corpus.py --compiler A --corpus C0 --evidence FILE freezes source inventory
  and performs one bounded production check. Repeat for C1.

Generate the 118 preliminary cells with v150-scale-fixtures.py --output DIRECTORY.
The complete C0/C1 inventories are separate cells. Use that directory with
v150-corpus-mutations.py --compiler A --fixtures DIRECTORY --evidence FILE and
v150-isolated.py --compiler A --fixtures DIRECTORY --userland ROOTFS --evidence FILE.
Isolation checks whole-project analysis and separate native generation/execution.

Run v150-measure-harness.py before v150-measure.py --compiler A --fixtures DIRECTORY
--output NEW_DIRECTORY. The latter serializes one warm-up and three recorded
fresh processes per cell. It retains raw streams, wait4 RSS, sampled RSS, timeouts,
signals and failures. An exit race has a bounded 100-ms RSS grace; an ongoing
unobservable process is a harness failure, never a zero-RSS success.
The 600-second and observed 4096-MiB cutoffs are preliminary observation
conditions, not adopted formal performance budgets. Preserve failed observations
under their original identity when correcting a harness or changing a candidate.

For an adopted formal budget, run v150-budget-harness.py and add
--formal-budget BUDGET_JSON to v150-measure.py. The frozen schema-1 record binds
the compiler, seed archive, C1 inventory and fixture-manifest hashes and supplies
wall-median, maximum-RSS and per-process cutoff limits for all 118 cells.
The formal command rejects partial selections, retains every failed observation,
and exits unsuccessfully when correctness, completeness or any budget fails.
One warm-up and three recorded runs are required; the warm-up must succeed but
is excluded from the wall median and maximum RSS.

Run v150-wall-cutoff.py to cover delayed reaping at both monitor exit paths.
The observer preserves actual exit/streams and marks an elapsed deadline overrun
as a wall cutoff even when the child already exited. The formal gate independently
checks every run's finite, nonnegative wall time, including the warm-up, against
its per-run cutoff before computing recorded-run aggregates.
Run v150-formal-recheck.py to verify the frozen 118-cell formal record with the
corrected gate, including all 472 run deadlines and 944 stream payloads. This
rechecks saved observations; it does not collect new performance samples.

The inherited native and parse resource gates above remain separate and unchanged.
The v1.4 acceptance ledger remains historical; do not rewrite its pinned identities
to make it claim v1.5 acceptance.

Once all observations are exported, verify their bindings and complete matrices:

~~~sh
python3 tests/mgnc/v150-implementation-evidence.py --evidence verification/v1.5.0-compiler --compiler A
~~~

This checks source/seed/artifact identities, input manifests, required results,
isolation, sample counts, existing budgets, and exact preliminary stream bytes.
It rejects incomplete preliminary data. Passing it records implementation
verification; formal v1.5 performance-budget adoption remains a separate decision.

The implementation-evidence command above validates the original fixed C1/A;
run it at pre-correction integration revision
6edf149259a1a5680127618b46c7b6442f425f94 with the original A. That revision
contains the checker and evidence while preserving the recorded source inventory.
A source or artifact mismatch is intentional rejection, not permission to relabel old data.
The [flow review correction](../../verification/v1.5.0-review-flow.md) records
its replacement candidate and affected verification separately.

## Whole-IR runtime components

The isolated v1.6 runtime probes generate and execute AMD64 ELF files through
Mognitio's own machine records and encoder. They do not change public compiler
commands or establish complete native-profile acceptance.

- `python3 tests/mgnc/v160-x64.py --seed PATH --output NEW_DIRECTORY` checks
  19 independently fixed instruction byte vectors and executes the resulting ELF.
- `python3 tests/mgnc/v160-runtime-plans.py --seed PATH --output NEW_DIRECTORY`
  checks concrete layout and liveness plans, including 17 invalid plans.
- `python3 tests/mgnc/v160-runtime.py --seed PATH --output NEW_DIRECTORY`
  exercises 29 generated runtime cases and five real syscall failure sites.
  Its independent physical-heap oracle checks reachable objects, coalescing,
  exact block-start indexes, free-list membership, and accounting. Cases include
  full-live and fragmented heaps, multiple arenas, stress collection, globals,
  partial construction, capture/return handoffs, twenty arguments, deep calls,
  invalid roots, and collector scratch growth.

Use a frozen, capability-verified seed. Linux AMD64 and ptrace support are
required for the execution and syscall fault probes. Terminal test exits are
component harness signals; they are not public runtime diagnostic acceptance.

## Full-backend acceptance runners

Use the same frozen candidate with these runners; each creates a new evidence
directory and preserves prior runs.

- v160-native-scale-run.py --compiler A --fixtures DIRECTORY --output NEW_DIRECTORY
  checks the 34 frozen native scale cases, independent ELF geometry, exact runtime
  streams and input inventories. A failed or interrupted build remains Failed;
  later cells remain NotRun. A --skip run is partial evidence only.
- v160-scale-run-harness.py exercises pass, failure, timeout, changed input,
  late inventory failure and partial selection using controlled observations.
- v160-native-extended.py --compiler A --output NEW_DIRECTORY checks 40 control,
  lifetime, module order, relocation, identity and publication observations.
- v160-native-isolation.py --compiler A --userland ROOTFS --output NEW_DIRECTORY
  builds and runs 41 values with no host toolchain or compiler sources visible.
  It records the unchanged userland inventory and requires executable mode 0755.

The scale runner's 900-second build and 120-second runtime guards only bound
functional exploration. This runner does not adopt or measure formal budgets.
