# Whole-program native runtime components

The isolated whole-program pipeline now emits native scalar and managed values,
closures, collections, UTF-8 text, module initialization, and the five admitted
text I/O functions. The public driver still selects the previous backend.
The new driver is exercised through a test-only override, keeping incomplete
whole-version acceptance separate from this component integration.

The [identity and observations](v1.6.0-native-runtime.json) fix the tested
implementation, seed, probe override, complete source inventory and executable.
The tested implementation is fb4d6df9fd691b0be9874e34b7ba1205cb63f24a;
the subsequent verification commit changes only these records.

## Behavior and validation

- 41 value/control/lifetime cases, 26 I/O observations and six module projects
  pass. Seventeen cases also pass with collection before every allocation,
  including more than 40,000 collections during partial construction.
- Eighteen syscall/resource fault observations and eight ownership failure
  cases pass. Each still-owned descriptor and scratch mapping is released
  once, cleanup preserves the primary failure, and a reused closed descriptor
  is not closed again.
- Native table and emitted-machine checks accept two valid inputs and reject
  eleven mutations with their specific expected internal diagnostic.
  Root/layout checks separately cover 52 frames, 76 descriptors and 17 mutants.
- Root verification indexes read/write positions once while retaining its
  independent forward read-before-write oracle. The earlier repeated full
  instruction scans timed out on the 256-specialization exploratory cell.
  The replacement's complete scale acceptance remains pending.
- The complete normal suite passes 236 groups, 605,733 assertions,
  1,316 native processes and all subsequent Python integrations.
- Toolchain-free Ubuntu 24.04 and 26.04 execution passes 100 inherited cases;
  Ubuntu 24.04 additionally passes the 41 new native cases. The v1.6 ELF
  header is checked independently; the former startup-opcode assertion is
  inapplicable because the managed runtime initializes its context first.

## Public cost structure

The ordinary emitter uses one cached length read, at most n-1 links for a
valid index, one fixed-size allocation per append, and one backward chain
transfer followed by forward iteration. Branching from an older snapshot
does not copy that snapshot. Scalars scans forward once and allocates one
small String and one List node per scalar. Join scans the chain twice,
allocates its result once and copies exactly the output bytes, with fixed
helper-frame space and no auxiliary managed list.

The 78 observed cells use n = 0, 1, 16, 64, 256, 1024; scalar widths 1-4;
and separator lengths 0, 1, 4, 16, including empty fragments.
Independent ptrace observation counts metadata/link operations, node and
String allocations, iteration entries and copied bytes. The instrumentation
adds only int3/event-ID pairs; the observer skips the event byte without
changing registers or flags. The source patch is versioned and its digest
is recorded. All observed counts equal their independent formulas.
Allocator/GC state is recorded separately; these observations are not formal
wall-time measurements. The observation probe predates the root-query index;
that compiler-only index does not change the emitted collection algorithms.
