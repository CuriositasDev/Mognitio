# Mognitio 1.8.0 acceptance and release validation

Version 1.8 specification, design, implementation, functional and performance
acceptance were explicitly accepted with authorization to release on 2026-11-16.
The accepted implementation includes repeated native generation and independent
restoration of the complete retained evidence. This record defines release
gates; it does not claim those distribution gates have already passed.
Publication is established separately by signed assets on the immutable v1.8.0
release and public package validation.

## Completed implementation acceptance

All 50 public cases and 19 internal entries passed the final evaluation, with
no Failed or NotRun rows in that evaluation. The functional closure contains
11 strict matrices, 52 mandatory gates and 26,544 observations. It binds the
source, producer graph, userland, measured target and independently fixed expected
results, including generation, compiler and consumer faults, isolation, source
variation and all-generation checks.

P0 passed 2,094 cells: 583 inherited cells and 1,511 new preliminary cells.
After numerical budget adoption, the separate P1 series passed all 1,511 new
formal cells and 6,044 observations. The fresh reclamation closure contains
54 cells and 216 observations. Original inputs, expected results, sample counts,
wall/RSS guards and adopted limits remain unchanged. Historical unsuccessful
candidates, Failed, NotRun and NotAdopted receipts remain preserved. No selective
rerun or relabelled preliminary sample substitutes for formal acceptance.

Subsequent helper review numerically checked the existing 6,044 observations
in each new P0/P1 series against every per-start guard. Strict functional helper
re-evaluation passed all 66 retained normalizations. These checks reused the retained raw evidence;
they did not rerun measurements or change accepted product sources.

`00f7d919ba35a5c48751f308c44265cd0db37299`: 262 Lisp test groups,
17,018,030 assertions, 1,371 native processes and zero failures.
The exact release candidate still requires its own complete-suite gate below.

## Source and distribution gates

The following gates remain pending at release preparation. Retain exact commits,
commands, frozen artifacts, workflows, raw evidence and results for each gate.

Run the complete normal suite at the exact release candidate. Verify the full
tracked checksum manifest and candidate/tagged source archives. Rebuild mgnc
from archived source with the verified qualified seed and require byte identity
with A before inheriting functional, isolation and performance evidence.
Re-run the applicable native contract, metadata, assertion and source/runtime
regressions against the release inputs.

Build one formal normal-toolchain payload from clean main and the locked Ubuntu
image, runtime, core and notice. Package the identical payload into Debian and
offline archives. Verify identity, bytes, permissions, installer failure/recovery,
protocol/analysis/projection/tokens, signing/trust and the unchanged consumer.
Verify real 1.7.0 offline upgrades on Ubuntu 24.04 and 26.04.

Freeze the draft assets, dispatch production signing with the exact manifest
hash and independently verify all downloaded bytes and signatures. Require the
signed package workflow to pass both supported userlands, including execution
as an unrelated unprivileged user after root installation, before publication.
Publish APT through its reviewed append-only registry and verify public HTTPS
signed-by upgrade, run/build/test/LSP, reinstall/remove/purge and standalone use.
Record actual publication results separately from implementation acceptance.

## Boundaries

Only mgn and mognitio-lsp are installed. mgnc remains experimental and source-built.
Repeated native generation is accepted in 1.8; ordinary CLI, test runner, LSP
and distribution replacement belongs to version 1.9. Normal toolchain and seed
identities remain separate. The accepted unused-witness specialization regression
also runs against the frozen normal-toolchain payload.

Linux amd64 / Ubuntu 24.04 and 26.04 are the package matrix. Namespace tests
share the host kernel and do not establish independent-kernel performance.
VS Code extension and Levi releases remain separate projects.
