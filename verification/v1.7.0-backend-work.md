# Bounded work in whole-project verification and encoding

Whole-compiler generation exposed two avoidable sources of temporary allocation.
Ownership walkers used absolute record positions as state keys, taking large
programs into a linear overflow map. Encoding put each short record or relocation
fragment directly through the complete carry tree.

The publication, directory, inspection and path walkers now key states relative
to the validated helper start. Each seen map belongs to that helper invocation.
Subtracting the same base preserves state distinctions and traversal order;
range checks still precede key construction. Diagnostics and all ownership,
cleanup and resource checks remain enabled.

Encoding still packs immutable record bytes directly. It buffers at most 4,096
bytes of small fragments before carrying them, passes large existing fragments
directly to the tree and preserves chronological concatenation. Label/size passes,
byte and field validation order, and the final independent length check remain.

## Validation

The [encoding oracle](../tests/mgnc/v170-encode-chunks.py) uses independently
constructed Python vectors and the frozen prior encoder. It covers 26 complete
ELF images, 20 carry/buffer series and all 17 malformed cases. The 46 files are
checked for complete bytes and modes. Empty fragments, mixed widths, both sides
of the buffer boundary and long runs of small records are included.

The [native allocation control](../tests/v170-encode-buffer.lisp) compiles the
actual carry implementation. Both paths check every output byte at three scales.
For 65,537 eight-byte fragments, buffered encoding must use at most one million
allocations; direct carry must exceed that bound. Allocation count is a structural
work check, not a wall-time or RSS budget.

The four existing filesystem machine-oracle harnesses also verify complete helper
regions after padding moves their absolute keys past the small-map boundary.
Their original malformed-helper cases remain mandatory. Independent frozen
old/new verifier comparisons check acceptance and complete diagnostics, including
source spans; runtime/type permutation checks retain their independent oracles.

These changes do not alter emitted program bytes or public contracts. Full
compiler regression, generated-compiler regression and newly generated complete
compiler generations remain required. Final version, consumer, isolation and
formal performance acceptance are separate gates.
