# Root propagation over complete control-flow graphs

A 256-closure build exceeded its 900-second exploratory guard. Sampling showed
root liveness repeatedly allocating and combining whole slot bitmaps. Numeric
block order did not follow CFG dependencies; a predecessor queue alone still
exceeded the guard.

Each block is now summarized once. An iterative DFS establishes successor-first
postorder independently of block numbering. Changes then revisit only affected
predecessors, retaining the same backward least fixed point. Instruction-level
root placement and the independent read-origin reachability verifier remain
unchanged.

The [identity and observations](v1.6.0-root-flow.json) bind the tested source,
S7 seed, probe candidate and unchanged scale fixture. The accepted final
increment is source 989a2121afd779a64dc0eb27a01d9dd6b2abfce6; this record adds no
compiler changes.

## Validation

- 144 CFGs agree with an independent oracle, including long cyclic and
  permuted graphs; 432 bitmap mutations are rejected.
- 52 frames / 76 descriptors and all 17 prior plan mutations pass.
- A 64-block permuted DAG updates each entry exactly once. Restoring the
  numeric queue order fails this independent work-count control.
- The same 256-closure build succeeds in 134.61 seconds and its executable
  returns the independently expected status 15 with empty streams.
- The same probe passes 90 native, 40 extended, and 41 isolated observations
  in each of Ubuntu 24.04 and 26.04.
- Normal tests pass: 242 groups, 1,889,890 assertions, 1,324 native processes,
  and all subsequent Python integrations. git diff --check passes.

performance result. Full scale, public Driver activation, same-candidate final
conformance and separately adopted formal budgets remain distinct gates.
No specification or design contract changes are required.
