# Machine-record page iteration

Machine checking and encoding repeatedly scan immutable pages of records.
A loop-over iterator materializes a buffer for each page, including a 552-byte
allocation for a full 64-record page. A fragmented heap may have ample total
free space but few blocks that can hold this temporary buffer.

The nine affected modules now read each existing page by index. The cursor
advances before the original body so continue keeps its original behavior.
Page order, record order, empty pages, the tail page, early returns, diagnostics
and encoded bytes retain their previous meaning. No checks, expected values,
runtime allocator policy, bootstrap seed, or resource limits change.

The implementation covers 17 scans in the machine, helper, contract,
publication, inspection, path and directory verifiers, native-table extent
calculation, and both encoder passes.

## Validation

The runtime-label oracle supports comparison with a previous source tree:

    python3 -B tests/mgnc/v170-runtime-label-oracles.py --seed "$SEED" --output "$OUTPUT" --compare-verifier-reference "$REFERENCE_COMPILER_SOURCE"
    python3 -B tests/mgnc/v170-encode-chunks.py --seed "$SEED" --output "$ENCODER_OUTPUT"
    sbcl --noinform --script scripts/test.lisp
    git diff --check

The reference directory contains src/. All seven verifier bodies are copied
under separate namespaces, including their dependencies on each other.
Acceptance and every diagnostic field must agree; mismatches abort instead of
being accepted as an expected rejection. Existing record mutations, shifted
layouts, type permutations and native execution remain required.

The encoder oracle compares complete output against its retained encoder and
an independently constructed ELF image. It includes record counts around page
and page-group boundaries, along with existing encoding errors and size cases.

Performance diagnostics must retain every fixed observation and compare emitted
artifacts. Include the original failing command paths as well as the fixed
small/large fixture matrix. A local improvement is not final version acceptance;
all candidate-dependent functional and performance evidence must be repeated
for a new frozen candidate.
