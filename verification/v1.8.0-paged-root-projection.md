# Paged managed-slot projection

Root projection previously appended each managed slot to a persistent flat
list. Repeated appends copied an increasing prefix while assigning dense root
IDs. The compiler now builds that sequence with the existing persistent
Paged<Int> representation.

Dense IDs still follow the original slot order. Expansion visits complete
pages followed by the tail and keeps the compact-bit index continuous across
page boundaries. Frame construction uses the stored count. Root selection,
use/kill transfers, frame maps, diagnostics and their source spans are unchanged.
The representation is internal to the compiler; language and runtime contracts
are unchanged.

## Validation

The exact compiler source was checked with direct projection and expansion
oracles, page-boundary and mixed-slot cases, diagnostic ordering and rejection
controls. Fresh hosted and native generations were checked, including identical
native compiler bytes across repeated generation. Thirteen native regression
jobs exercised the existing verifier, dataflow, root-flow, root-order, paged-index
and whole-IR tests plus focused projection cases.

A fixed comparison covered 15 cases and 88 starts using unchanged inputs,
expected outputs, numeric budgets and single-start guards. All prototype cases
fit those existing numeric limits. Every generated program matched its expected
bytes and executable mode. The baseline specialization case still exceeded its
30-second median limit; that failed result is retained.

These are scoped implementation checks. They do not replace acceptance of a
fresh candidate from integrated main, complete version performance coverage or
the final archive and restoration checks. Diagnostic timings are not formal
performance results. Existing failures and unstarted work remain recorded.
