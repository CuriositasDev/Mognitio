# Storage getter regeneration

The scalar-page generator still emitted the earlier ItemStorage and NodeStorage
getters after the checked reader optimization. Running it replaced those
optimized getters, so regeneration failed the exact compiler-source comparison.

The generator now emits the existing cached page/lane selection and direct
record construction for ItemStorage and NodeStorage. TokenStorage generation,
bounds diagnostics, output membership and all compiler-source bytes are unchanged.

## Validation

The generator's --check mode passed. Writing all three generated storage modules
in an independent tracked-source archive reproduced all 296 compiler files,
including the 293 Mognitio sources, byte-for-byte.

The implementation test commit passed the complete scripts/test.lisp command:
260 Lisp tests, 16,993,180 assertions, 1,371 processes and 29 Python suites, with
zero failures. The qualified test adapter reaped exactly three already-terminated
fixture processes with their expected wait statuses; the independent observer
reported no residue. The 7,200-second and 8-GiB guards were unchanged.

The final commit adds only this note, its index entry and checksum updates after
that tested commit. The original failed regeneration and three unrun provenance
jobs remain retained. Fresh candidate provenance, functional/performance
acceptance and final archive restoration remain separate gates.
