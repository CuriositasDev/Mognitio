# Wider persistent radix map

The compiler's integer-key map previously moved keys at or above 1,048,576
into a persistent linear list. Whole-program label verification can cross that
boundary, causing repeated list scans and copies even though labels remain
ordinary nonnegative integers.

The generated four-way tree now has twelve levels and covers keys below
16,777,216. It preserves missing-key results, negative-key diagnostics, exact
Int64 keys above the boundary, replacement, and all earlier snapshots. The
generator derives every depth, divisor, and limit from one level count.
Global label uniqueness is still checked across all procedures.

## Checks

```sh
python3 tests/mgnc/generate-int-map.py --check
python3 tests/mgnc/v170-int-map.py --compiler /path/to/compiler
sbcl --noinform --script scripts/test.lisp
git diff --check
```

The cumulative suite compiles the current module and a frozen ten-level
reference against the same independent boundary and snapshot fixture. It covers
17 boundary keys, all twelve radix positions, dense updates around both limits,
and exact high-key replacement. Forced collection checks live tables and old
snapshots in four key regions.

Native allocation counters compare 64, 256, and 1,024 entries, with two updates
and four queries per entry. The expanded range must stay within linear count
and byte bounds. The old reference exceeds 64 MiB at 1,024 entries in that
range, distinguishing the implementations. Small-key overhead is bounded
against the old tree; adding two levels is a deliberate space tradeoff.
The fallback above the new limit retains its old cost characteristics.

These operation/allocation checks do not establish whole-compiler generation,
formal wall-time or RSS budgets, or release readiness.
