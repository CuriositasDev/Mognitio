# Concrete instances and closure planning

Native planning now identifies allowed standard symbols by resolved identity,
retains immutable symbolic bodies, and specializes bodies using complete lexical
compile-time bindings. Creation targets reference concrete body instances;
runtime capture values do not enter the instance key. Closure plans map each
creation input to a typed environment field and each field to its callee slot.

Independent checks derive source/instance correspondence, substitute type graphs
without calling the producer, check root and creation-edge membership, and
recheck definite assignment and variant guards after substitution. Closure
checks verify field identity, input source, target instance and complete site
membership. They compose with the source-based capture verifier, including
module snapshots and nested capture propagation.

The [machine-readable record](v1.6.0-native-planning.json) binds the source,
immutable bootstrap, native probe and fixture hashes. This infrastructure is
isolated from the public build path until the expanded backend is ready.
The public check/lower/build commands retain their previous behavior.

The probe passes 31 standard-identity/profile cases and six fixed generic cases,
including body-only type/value bindings, nested callees, mixed argument kinds,
Int/String/Int reuse and owner-typed Result propagation. Four valid internal
controls, including reversed instance IDs, pass. Ten concrete-plan mutations
and four closure-plan mutations are rejected by asserted internal diagnostics.

The complete normal-suite result is recorded with the pull request. This slice
does not establish machine-code emission, GC/ABI or native execution support,
complete v1.6 acceptance, formal performance acceptance or release.
