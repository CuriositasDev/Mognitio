# v1.5 operator and module-flow review correction

## Findings and behavior

Both findings against main 6edf149 were reproduced on the original fixed A.
A non-completing Unknown operand incorrectly prevented unique ordinary Int
operator selection. Separately, each module initializer started independently,
so a later runtime declaration escaped unreachable-sequence checking.

The correction selects the unique ordinary operator when no operand supplies
a known structure. Addition and equality remain ambiguous in that situation.
Known fixed-width integers, Bits and incompatible structures keep their
existing rules. Each module now carries initializer normal completion to its
next runtime declaration. Compile-time declarations neither execute nor reset
that state. Calls are not analyzed for termination, and unused modules are
checked as before.

The accepted S2 requires no change. S2 builds the unary-negative and subtraction
reproducers, whose executables return 7, and rejects the unreachable declaration.
Those seed observations are retained separately from the new compiler results.
