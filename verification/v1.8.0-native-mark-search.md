# Bounded native mark searches

Generated runtimes reject a pointer outside the first and last sorted static
object addresses before performing the exact static-object binary search.
Pointers inside that interval still require an exact entry and a valid static
leaf descriptor.

For heap pointers, arena metadata slot 56 holds the most recently matched
arena. The hint is range-checked before use. A miss falls back to the original
arena list, and a newly mapped arena starts with a zero hint. Arena ranges stay
valid through collection; block-start bitmap, extent, descriptor and allocation
state checks still run on every hit, including already-marked objects. Sweep
therefore does not need to clear this range hint.

The context layout, managed object headers, helper ABI, allocation order,
collection policy and descriptor traversal remain unchanged. This hint occupies
the previously unused arena header word before the allocator cursors at offset
64; it adds no allocation or system call.

## Independent emitted-byte controls

The focused harness compiles the actual mark emitter and runs its machine
records against separately constructed static tables, arenas, bitmaps and a
first-enqueue oracle. It covers every entry of a 1,024-object static table,
128 disjoint arenas, repeated references, a new head arena, empty tables, null
roots, invalid interior pointers and bitmap, extent, descriptor and state
failures. Removing instrumentation must preserve enqueue order.

For 4,096 repeated references to the last of 128 arenas, static binary-search
probes must be zero and arena range probes at most 4,224. Five mutations disable
either search optimization, omit either cached range bound, or bypass cached
pointer validation; each must fail a semantic or structural-work check, or
terminate its isolated child through the internal or memory-protection guard.

Run the focused controls with:

    python3 tests/mgnc/v180-mark-search.py --compiler bin/mgn --output /tmp/mark-search-check

These are semantic and structural-work checks, not adopted wall-time or RSS
budgets. A changed runtime requires new dependent compiler generations and
fresh functional, determinism, isolation and performance acceptance.
