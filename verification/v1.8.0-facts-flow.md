# Bounded bitmap edits and dataflow retention

Repeated definitions previously rebuilt an entire immutable bitmap for every
write. Dataflow updates also retained all old versions while only the newest
head for each reachable block was needed.

## Internal behavior

Facts equality checks length before indexing backwards through both vectors.
Defining an already present bit returns the unchanged immutable input. The
definition path still checks mask validity before slot bounds; reads check
bounds before masks, preserving diagnostic priority and source spans.

A WordEdit stores an immutable base and one pending word. Writes to that word
combine bits without rebuilding the vector. Changing words flushes the prior
pending value. Reads include the pending word, and finishing an edit produces
the same bitmap as the original sequence of definitions. Earlier inputs and
edit snapshots remain observable.

WholeDataflow stores the newest Facts for each block. Before an accepted update,
when the retained count divided by two reaches the reachable block count N,
compaction copies current heads in the existing reachable order to a fresh
Paged and Map. Absent heads keep the full fallback. For N >= 1, at most 2N
versions remain after each update; division avoids multiplying a bounded Int.
At most N versions are copied per compaction, with at least N intervening
updates. Existing Flow snapshots remain immutable.

Worklist order, predecessor intersections, guard invalidation, diagnostics and
origin spans are unchanged. This correction changes no runtime ABI or allocator
policy.

## Reproduction

Run each command with a clean output directory and the selected compiler:

~~~sh
python3 -B tests/mgnc/v180-facts-flow.py --compiler SEED --program-mode 0700 --output SEED_OUTPUT
python3 -B tests/mgnc/v180-facts-flow.py --compiler NATIVE_COMPILER --program-mode 0755 --mutants --output NATIVE_OUTPUT
sbcl --noinform --script scripts/test.lisp
sha256sum -c verification/SHA256SUMS
git diff --check
~~~

The fixed language fixtures retain independently calculated integer and dictionary
expectations: 132 equality cases, 258 definition cases, 18 edit sequences with
180 writes and 3759 reads, and 22 flow cases with 3815 updates and 179 old
snapshot checks. They cover sparse/reordered IDs, missing heads, empty inputs,
repeated writes, word/page boundaries, negative slots and exact diagnostics.

All selected namespace files are copied whole. Compaction tests append diagnostic
exports to the complete product module and check that the threshold and append
statements match production. This private helper oracle complements the existing
19-case dataflow fixture and native verifier/root regressions; it does not replace
those paths. Nineteen deliberate mutations must fail at their exact first
counterexamples after successfully building.

## Acceptance boundary

Private fresh native regeneration, hosted/native byte equality, verifier/root
regressions and all 80 starts of a fixed 14-case comparison were independently
checked. Existing limits were preserved. The bounded variant fit these diagnostic
limits, including the previously failing wide-build RSS case. Other cases can be
slower than the baseline; no universal speedup is claimed.

Earlier failures and unsuccessful alternatives remain evidence. Integration
requires implementation gates and review. A new candidate from integrated main
must repeat full functional and performance acceptance. Private images are not
promoted to official candidates, and these diagnostics do not establish version
completion or release.
