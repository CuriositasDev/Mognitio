# Allocation lifetime in compiler traversals

Candidate-dependent preliminary measurements exposed high retained memory in
semantic pruning and repeated allocation searches during encoding and builds.
This internal correction preserves source diagnostics, node order and emitted
program bytes except for the declared native reserve threshold.

## Traversal and reserve policy

Classification.prune stores each visit ID and parent in one frame. Eight
frames form a scalar page; only the unfinished tail contains frame objects.
Pages remain append-only, so recorded parent indices keep their meaning.
Left, right and alternative children are visited in the same order, with
short-circuit selection of the first unresolved child. An empty rejection set
does not require a lookup. Memoization, shared nodes, alternative promotion and
source metadata keep their existing behavior.

After a no-fit collection, an uncapped, non-stress generated runtime now
considers optional reserve growth above 64 MiB mapped. Exactly 64 MiB and
smaller heaps retain the old retry. Only blocks fitting the current request
contribute to the reserve, whose target remains one eighth of mapped bytes,
capped at 128 MiB. Optional mapping failure retries an existing fitting block;
mandatory mapping failure retains the existing failure behavior.

The arena-capacity policy has its separate 512 MiB boundary. Heap caps, forced
collection, first-fit order, cursor repair and sweep reset are unchanged.
No runtime context, descriptor, object header or value ABI changes.

EncodeChunks.combine reads fragments by index rather than constructing an
iteration buffer. Adjacent pairing, the balanced concatenation tree, odd
carries, empty input and the 4096-byte buffering policy are unchanged. Indexing
has its existing cost; this change targets allocation lifetime, not a new
constant-time indexing guarantee.

## Focused reproduction

Use the qualified seed and a clean output directory for every command:

~~~sh
python3 -B tests/mgnc/v180-prune-storage.py --source compiler/mgnc --baseline BASELINE_SOURCE --seed SEED --output PRUNE_OUTPUT
python3 -B tests/mgnc/v180-fit-cursors.py --compiler COMPILER --output FIT_OUTPUT
python3 -B tests/mgnc/v180-arena-capacity.py --records FIT_OUTPUT/records.txt --output CAPACITY_OUTPUT
python3 -B tests/mgnc/v180-post-collection-reserve.py --records FIT_OUTPUT/records.txt --output RESERVE_OUTPUT
python3 -B tests/mgnc/v180-mark-search.py --compiler COMPILER --output MARK_OUTPUT
python3 -B tests/mgnc/v170-encode-chunks.py --seed COMPILER --output ENCODER_OUTPUT
sbcl --noinform --script scripts/test.lisp
sha256sum -c verification/SHA256SUMS
git diff --check
~~~

The recursive pruning oracle checks all nodes and roots in 16 bounded forests,
including shared and forward references, rejected ancestors, promotion,
metadata and a 521-node chain crossing the 65th frame page.
It compares both implementations against independently calculated output.

The reserve oracle covers 16 normal scenarios, seven deliberate mutations and
three mandatory mapping failures. The 64 MiB boundary, unchanged capacity
boundary, capped/stress paths, fragmented space, failed optional mapping and
128 MiB saturation are explicit controls. The capacity and first-fit tests
continue to use the actual emitted instruction records.

The encoder oracle checks 34 complete ELF images, 29 carry/buffer series and
17 negative diagnostics against legacy and independently constructed results.

## Evidence and acceptance boundary

Private source-built diagnostics passed the recursive oracle, four producers'
100 allocator control groups, native regeneration and hosted/native byte
equality. All 62 native comparison starts retained the original exits and
streams; generated programs differed only at the declared runtime threshold.
The separate six-start hosted comparison also preserved its output.

The paired diagnostic medians were about 787 and 755 seconds for native whole
builds, 34 seconds for the wide binary build, and 1161 seconds for the hosted
whole build. These fit the existing limits in this diagnostic. Baselines varied
between runs; these values do not establish a universal improvement ratio.

Earlier budget overruns and unsuccessful alternatives remain evidence.
Implementation gates, a newly frozen candidate, complete functional acceptance,
fresh preliminary measurements, canonical budget binding and formal performance
acceptance are separate requirements. Neither these diagnostics nor integration
of this correction establishes version completion or release.
