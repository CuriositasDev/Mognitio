# Repeated native generation evidence foundation

The experimental generation harness records immutable candidates, producer
edges, exact output bytes and modes, per-attempt observations, and independently
versioned regression expectations. It does not replace the normal toolchain.

A source manifest includes every file, including unused modules and generated
tables. Its inventory is rechecked before generation and after execution.
Native edges mount one verified producer and the whole input source read-only
in a fresh non-root namespace; only bootstrap mounts the frozen Lisp seed.
Outputs start empty. A failed command, cutoff, observation failure, changed
input, or remaining child cannot produce an accepted artifact.

The raw comparator independently detects bytes, length and mode changes.
Equal hashes do not merge generation roles or producer relationships. Suite
evaluation preserves missing cells as NotRun and retains unsuccessful attempts.
Filesystem ledgers retain binary names, modes, symbolic links and hardlink
relationships for restoration checks.

The fresh observer retains the existing command wall and kernel RSS accounting,
adds the full sampled RSS series, and runs each observation in a new process.
Its kernel peak includes the fixed worker floor; it does not subtract that floor.
Missing short-process samples are null, not zero memory. Controls cover failure
streams, wall/RSS cutoffs, child cleanup, and retained/freed controller memory.

Run the focused controls from the repository root:

```sh
python3 tests/mgnc/v180-evidence-tests.py
python3 tests/mgnc/v180-observer-tests.py --output /path/to/new-observer-results
git diff --check
```

This foundation is not whole-version acceptance. Seed requalification, actual
full generation and repeated fixed-point comparisons, all-generation language
and consumer regressions, faults, both userlands, inherited performance, newly
adopted numerical budgets, and restored final evidence remain separate gates.
No release or ordinary toolchain migration is implied.
