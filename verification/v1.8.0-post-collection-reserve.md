# Fitting reserve after native collection

When an uncapped generated runtime has more than 512 MiB mapped, a collection
may reclaim only a small tail that fits the current request. Immediately
consuming that tail previously caused another full collection after very little
allocation. Increasing arena capacity alone does not repair this condition:
a reclaimed fitting block prevents mandatory arena growth.

After a no-fit collection, the allocator now sums only free blocks large enough
for the pending physical request. If that sum is below one eighth of mapped
space, capped at 128 MiB, it attempts one arena extension before retrying the
ordinary first-fit search. The sum scan stops once the reserve is sufficient
and retains a mapped-space-derived traversal bound.

Heaps at or below 512 MiB, explicit heap caps and forced-collection mode retain
the original retry behavior. Scheduled collection and allocation-fault ordinals
retain their existing semantics. Capacity, page rounding and bitmap geometry
follow the [arena capacity policy](v1.8.0-native-arena-capacity.md).

## Mapping failure and allocation order

The arena helper reports mmap failure to its caller. With no fitting reclaimed
block, mandatory growth failure still reaches allocation failure. When a
reclaimed block fits, optional growth failure retries that existing block.
Overflow and invalid geometry remain errors.

Successful growth uses the existing native arena/free-list head insertion.
Allocation searches that resulting list in first-fit order and retains all
cursor ownership, repair and sweep-reset rules. This adds no context fields
or managed-object header changes.

## Independent controls

The focused harness runs actual emitted allocator and arena bytes. A controlled
collector stub exposes a separately constructed reclaimed free chain, counts
collections and preserves the helper ABI. Seven positive scenarios cover the
threshold, sufficient/insufficient reserve, fragmented holes, explicit caps,
stress mode and optional mmap failure. The mmap fault replaces only the actual
arena syscall; no successful mapping is fabricated.

Six identified mutations change the threshold, cap/stress exclusions, fitting
filter, reserve fraction or optional-failure fallback. Each must fail an
independent allocation/geometry oracle or take the deliberately incorrect fatal
path. A separate no-fitting-block case confirms mandatory mmap failure exits
through the allocation-failure guard.

Run from the repository root:

    python3 tests/mgnc/v180-fit-cursors.py --compiler bin/mgn --output /tmp/reserve-records
    python3 tests/mgnc/v180-post-collection-reserve.py --records /tmp/reserve-records/records.txt --output /tmp/reserve-check

The existing first-fit, sweep, pointer-validation and complete compiler suites
remain required. Whole-compiler diagnostics and binary-patched images do not
establish functional or performance acceptance. Freeze new compiler inputs,
regenerate all dependent images and repeat the required acceptance gates.

## Subsequent threshold correction

The original 512 MiB trigger and its evidence above describe this increment.
[Compiler traversal allocation lifetime](v1.8.0-allocation-lifetime.md) records
the later 64 MiB reserve trigger, expanded controls and separate acceptance
boundary. The arena-capacity threshold remains 512 MiB.
