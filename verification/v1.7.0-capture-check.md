# Capture verification allocation

Capture membership uses persistent integer-keyed indexes instead of creating a fresh
iteration buffer for each lookup. The module-closure prefix indexes only
preceding `global-load` operations: other operations never satisfy that check.
The prefix retains every preceding output/symbol pair, including earlier loads when a
later load targets the same output with a different symbol.

The independent verifier still derives captures from resolved semantic uses,
checks frame membership and ordering, and rejects incomplete or incorrect
closure mappings and missing module loads. This changes no source contract,
IR producer, emitted program behavior, or performance budget.

Run the focused native oracle with a qualified bootstrap compiler:

```sh
python3 tests/mgnc/v170-capture-check.py --seed /path/to/mgn --output /tmp/capture-check
```

The oracle includes whole-source ID permutations and thirteen existing IR
mutations, plus module-prefix controls and eight capture-specific mutations.
It requires six valid configurations and twenty-one rejected mutations.
The original closure-scale performance fixtures and budgets remain unchanged.
