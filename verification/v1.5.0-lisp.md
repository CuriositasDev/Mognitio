# v1.5 Lisp path inspection

This increment implements the additional path capability in the Lisp compiler
and its generated Linux amd64 programs. It does not change the experimental
`mgnc` implementation, freeze a seed, accept the implementation, or release 1.5.

## Implemented boundary

- `inspectPath: Function(String): Result<PathInfo,PathInfoError>` is an ordinary
  explicitly imported function value.
- `PathInfo` contains `kind: DirectoryEntryKind` and `identity: FileIdentity`.
  `PathInfoError` contains `kind: IoErrorKind` and the original `subject: String`.
- `FileIdentity` is opaque, immutable, and supports same-type `==` / `!=`.
  Both complete unsigned device/inode words participate; comparison performs no I/O.
- Empty/NUL paths fail before observation. Trailing slashes are removed except
  root; interior components are left to the OS. Final symlinks are observed
  directly, including dangling links, while intermediate links are followed.
- One successful `fstatat` supplies kind and identity. FIFO/socket inspection
  does not open or read their contents.
- Native scratch mappings are registered before use and released before result
  allocation. Host scratch storage is managed memory, without invented close calls.
  OS errors remain values, while allocation/internal failures keep their existing exits.
- Existing public enum variants and `IoError` fields remain unchanged.

The host backend also quotes the Unit value returned by `assert` and test
staging. This fixes an existing unbound-symbol failure exposed by SBCL 2.2.9;
the newer development SBCL had optimized away the discarded reference.

## Reproduce

```sh
sbcl --noinform --script scripts/test-v150-lisp.lisp
python3 tests/v150-inspection.py
sbcl --noinform --script scripts/test.lisp
python3 tests/mgnc/acceptance.py
git diff --check
sha256sum -c verification/SHA256SUMS
```

The focused suite requires non-root Linux amd64, SBCL, Python, strace and a
writable `/dev/shm` on a different filesystem from the temporary project.
The cumulative suite retains its existing ACL/group prerequisites.
Private test hooks are not exposed through language APIs or CLI options.

## Evidence scope

The focused tests cover static positive/negative contracts, function storage,
aliases/generics/Product/Sum/List/Result/captures, forced GC, actual filesystem
observations, error classification, EINTR, allocation failure, cleanup precedence,
repeated resource ownership, and descriptor/IR/machine mutations.
Synthetic internal objects exercise high bits of both identity words without
adding a public constructor. Real stat values are compared with an independent
host adapter. CLI integration includes rename/content changes, post-deletion
comparison, Unicode/control/backslash names, permissions, and compiler-free
native execution.

Final validation results and source identity are recorded separately after the
candidate checks complete. Implementation acceptance and seed freeze remain
distinct subsequent decisions.
