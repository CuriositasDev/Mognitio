# Adaptive capacity for generated native arenas

Generated runtimes previously limited preferred arena capacity to 16 MiB,
including heaps retaining hundreds of MiB of live objects. The native emitter
now selects one eighth of mapped space, capped at 128 MiB, when an uncapped
heap exceeds 512 MiB. At or below that boundary, the existing one-quarter policy
with its 1 MiB minimum and 16 MiB maximum is unchanged. A physical request
larger than the preferred capacity still determines the payload capacity.

An explicit mapped-heap cap retains the previous arena geometry. Allocation
still searches and collects before growth. The subsequent
[post-collection reserve](v1.8.0-post-collection-reserve.md) can also attempt an
optional extension when fitting reclaimed space is scarce. Page rounding,
bitmap capacity, mapping accounting, overflow checks, mmap error handling,
object headers and first-fit cursor repair retain their existing behavior.

## Independent emitted-byte verification

The policy harness executes records emitted by the actual WholeArena module.
An independent unsigned arithmetic oracle checks 144 combinations, including
both sides of the 512 MiB boundary, reserve saturation, explicit caps, requests
larger than reserve and the full 64-bit mapped-space range. A test-only return
after capacity selection avoids attempting enormous diagnostic mappings.

Four real mappings check payload/bitmap geometry, mapped-byte accounting and
zeroed cursor metadata. Five identified mutations change the threshold, either
cap, explicit-cap exclusion or large-heap growth rate. Each must be rejected by
the independent policy oracle.

Run from the repository root:

    python3 tests/mgnc/v180-fit-cursors.py --compiler bin/mgn --output /tmp/arena-records
    python3 tests/mgnc/v180-arena-capacity.py --records /tmp/arena-records/records.txt --output /tmp/arena-capacity

The first command also runs the existing independent first-fit and sweep controls.
The complete compiler regression suite remains required. These checks establish
the capacity policy and local runtime invariants; they do not establish a
whole-compiler speedup or adopt wall-time or RSS budgets.

Changed runtime source requires a fresh candidate, new dependent compiler
generations, determinism comparisons and functional/performance acceptance.
Previously failed generation receipts remain failed. Diagnostic binary patches
cannot serve as compiler-generation acceptance evidence.
