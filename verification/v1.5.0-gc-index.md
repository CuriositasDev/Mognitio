# v1.5 native GC lookup repair

The growing compiler exposed linear scans over every descriptor and every static
root during collection. Exact-address dispatch now uses balanced comparison trees
over each table's emission order. Root candidates are compared without
dereferencing them. The existing allocated-start, object-kind, size, variant,
closure, interface and reference-layout checks still run.

The descriptor table and static-object table follow metadata-unit order; text
roots use their separate literal-ID order. No ordering between these different
tables is assumed.

## Validation

- sbcl --noinform --script scripts/test.lisp: all existing 230 Lisp groups,
  9,603 assertions and 1,313 child processes passed. The complete subsequent
  Python integration sequence also passed, including all 55 v1.5 path checks.
- The two added GC tests passed separately: 24,495 assertions and one native
  process. An independent association oracle checks every exact start and gap
  for nine table sizes, including unsigned high-word addresses and empty tables.
  It also checks the logarithmic comparison bound. A stress artifact retains
  96 distinct nominal descriptors and their static text roots across collections.
- git diff --check passed.

These runs exercised the runtime change at source revision
c4db266960c147518261bef2558cdc69b4438b6b. The new tests were added after the
existing full run started and were therefore run separately.

acceptance, formal performance-budget adoption and release remain separate.
