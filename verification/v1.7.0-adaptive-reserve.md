# Bounded reserve for large native heaps

A fixed 16 MiB reserve made large live graphs collect repeatedly after a small
amount of temporary allocation. The allocator now retains that cap through
512 MiB of mapped heap, then uses one eighth of mapped space capped at 128 MiB.
The same policy bounds proactive reserve and arena growth. Requests larger than
the reserve still receive enough space for their complete physical allocation.

The [allocator](../src/native-memory.lisp) preserves explicit arena geometry and
heap caps, first-fit selection, cursor repair, and the fallback that uses an
existing fitting block if optional reserve mapping fails. Context layout and
value ABI remain unchanged.

## Independent validation

The [policy tests](../tests/v170-adaptive-reserve.lisp) interpret actual emitted
unsigned operations at the threshold, at cap saturation and across the full
64-bit range. Forty observations cover both policy sites. Six mutations alter
the threshold comparison or either cap; the independent arithmetic oracle must
reject each. Explicit arena-unit and heap-cap controls exclude the adaptive
branches.

A [native retained/dropped graph](../tests/fixtures/v170-live-reserve.mgn) keeps
twelve million cells and their list live while allocating and dropping twelve
million more cells. The result and all 36,000,002 allocation events must match.
Both variants exceed 1 GiB of mapped heap and stay below a 1,536 MiB mapped
bound. The adaptive variant requires at most 80 collections; disabling only the
two large-heap branches preserves values but exceeds that bound. Mutation
membership is checked before building the control image.

Existing small-heap, pointer-validation, lifetime, cursor, fixed-geometry and
optional-mapping-failure tests remain required. The complete compiler suite and
host-generated compiler regressions cover affected consumers.

These collection counts and mapped-space bounds are structural checks. They do
not establish formal wall-time or observed-RSS budgets, and concurrent exploratory
generation is not a formal performance measurement.

## Bootstrap boundary

This runtime change requires a newly frozen and qualified seed before its
compiler images can become bootstrap acceptance evidence. Existing qualified
seeds remain immutable. Rebuild dependent compiler generations and rerun their
functional, isolation, determinism, resource and performance gates with the final
candidate. Implementation validation alone does not complete version acceptance.
