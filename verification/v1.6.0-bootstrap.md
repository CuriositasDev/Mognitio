# v1.6 bootstrap acceptance

The accepted v1.5 replacement seed is selected explicitly for v1.6 compiler
development after a fresh capability audit. Its original archive, receipt and
715 components remain unchanged. No Lisp repair or new public API was required.
This accepts the bootstrap prerequisite, not the v1.6 compiler implementation,
native runtime, formal performance or release.

## Capability and restoration evidence

Five programs each pass host execution, native generation and native execution:
module variable snapshots before/after rebinding; nested-only module captures;
alternating generic capture types; Result error reconstruction with different
success types; and 8,192 structured arena records with persistent snapshots.
Together with full-compiler generation and check, these are 17 observations.
Expectations and fixture hashes are written before execution.

The cumulative suite passes 232 Lisp groups, 34,098 assertions and 1,314
harness processes, followed by the complete Python integration sequence.
This includes existing collection, GC, I/O, numeric, binary, publication,
module, analysis and path-inspection regressions.
These checks validate the unchanged Lisp implementation and its runtime.

The archive is authenticated against its receipt before isolated restoration.
All 715 component identities are verified, an altered launcher is rejected,
and isolated run/build plus execution of the standalone output succeed.
Eleven prospective lower-command fixture groups are also materialized and pass
the existing semantic checker. They are not recorded as successful lower tests.

## Reproduction

~~~sh
python3 scripts/freeze-seed.py --verify VERIFIED_SEED
python3 tests/v160-seed-capability.py --seed VERIFIED_SEED --output NEW_AUDIT_DIRECTORY
python3 tests/v150-seed.py --bundle SEED_ARCHIVE --receipt verification/v1.5.0-seed2.json
sbcl --noinform --script scripts/test.lisp
python3 tests/mgnc/v160-lower-cases.py --compiler GENERATED_COMPILER --mode check --output NEW_FIXTURE_DIRECTORY
git diff --check
~~~

Development checks used SBCL 2.2.9 explicitly. Timing observations are not formal
v1.6 budgets. Compiler changes must rebuild their own artifact with this seed;
a newly discovered seed deficiency requires repair, acceptance and a new frozen
identity before dependent work proceeds.
