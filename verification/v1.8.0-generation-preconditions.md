# Generation candidate preconditions

The isolated generation runner checks the complete runtime inventory against
the candidate compiler source subtree before creating an output directory.
Bytes, modes, file membership, source revision and the inventory aggregate must
agree. A separately recorded runtime cannot silently describe another source.

The runner also checks its supported Linux AMD64 target and inherited ABI,
the fixed bootstrap/native output modes, process umask and exploratory wall/RSS
guards. A changed target or policy requires a corresponding runner rather than
a label change in the candidate record. These exploratory guards are not
adopted performance budgets.

Focused controls reject changed runtime bytes and modes, missing or extra
files, revision and aggregate mismatches, wrong runtime roles, changed target
or ABI, changed guards and an incompatible process umask. A target mismatch
is rejected before the observer runs or an output directory is created.

This change affects evidence preconditions only. Compiler sources, generated
runtime algorithms and language behavior are unchanged. Completed artifacts
may be checked against the added preconditions without relabelling their old
receipts; whole-generation and performance acceptance remain separate gates.
