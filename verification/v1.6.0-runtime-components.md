# Generated runtime components

The compiler now contains concrete object-layout planning, backward root
liveness, source-call frames, AMD64 instruction builders and a generated
nonmoving collector. Independent forward read-before-write checks validate root
bitmaps; a separate layout checker validates nominal descriptors, active sum
payloads, closure fields and typed iteration buffers.

The allocator reuses indexed arenas and coalesced free blocks. Marking verifies
object bases against arena ranges and block-start bits before reading headers.
An iterative worklist uses separately owned mmap/mremap scratch; sweep rebuilds
the index and free-list. Collection thresholds follow live bytes. Scalar-only
collector helpers preserve the language callee-save registers. Source frames
register precise roots after copying incoming values and return without a
safepoint before the caller saves RAX.

The [machine-readable record](v1.6.0-runtime-components.json) binds tested source,
bootstrap and generated artifacts. These components remain isolated from the
public build path while complete native emission is developed.

## Validation

~~~sh
python3 tests/mgnc/v160-x64.py --seed VERIFIED_SEED/bin/mgn --output NEW_DIRECTORY
python3 tests/mgnc/v160-runtime-plans.py --seed VERIFIED_SEED/bin/mgn --output NEW_DIRECTORY
python3 tests/mgnc/v160-runtime.py --seed VERIFIED_SEED/bin/mgn --output NEW_DIRECTORY
sbcl --noinform --script scripts/test.lisp
git diff --check
~~~

- 19 independent AMD64 byte vectors and generated ELF execution pass.
- 52 concrete frames and 76 descriptors pass; nine root and eight layout
  mutations fail at the asserted independent checks.
- 29 generated runtime cases pass an independent physical-heap oracle or their
  expected fault exit. The oracle checks graph reachability, physical sizes,
  free-list completeness, exact block-start indexes, coalescing and accounting.
- The retained 50,000-node graph survives 250,000 total allocations; after
  clearing its root, both arenas contain only free blocks. Physical live size
  includes the allocator's unsplittable tail, checked by summing object headers.
- Full-live, fragmented, multi-arena, stress, variant, buffer, static, global,
  capture and partial-construction cases pass. Twenty arguments and 1,000 nested
  calls preserve roots, return handoffs, alignment and callee-save sentinels.
- Five actual mmap/mremap failure sites produce the component allocation-failure
  exit, including collector scratch creation and growth.
- The full normal suite passes 236 groups, 605,733 assertions and 1,316 native
  processes, followed by all Python integrations.

These are component results. Complete native instruction selection, emitted
program verification, public runtime diagnostics, I/O cleanup, final corpus
acceptance and formal performance acceptance remain outstanding. Component
harness exit codes do not replace public failure contracts.
