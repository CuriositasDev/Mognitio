# Unused witness specialization type closure

The v1.6.0 reference source, a3d1ec09c023f09e6f6da526fa5cf64f030c5e80,
rejects a valid project importing an unused named witness with the internal
diagnostic `Unregistered concrete type`. Packaging the same witness succeeds.
The frozen S10 seed reproduces this difference as well.

Specialization retains every checked implementation in the concrete dispatch
table. Its type worklist previously followed function bodies and signatures;
the unused contract identity could therefore be absent when copying the table.
The planner now closes both identities of every implementation pair, using the
same recursive type traversal and deterministic ordering as other concrete types.
Evidence visibility, project-wide pair uniqueness and public signatures remain
unchanged. No source syntax or public API is added.

## Focused regression

```sh
python3 -W error tests/v170-witness.py
git diff --check
```

All nine cases and 25 observations pass. Cases cover unused imports, an import
alias, an unreachable module, ordinary dispatch, private implementation hiding,
unused nested signature types and multiple concrete implementations. Missing
visible evidence and duplicate pairs in unreachable files remain semantic
errors and preserve an existing output. Successful builds produce executable
ELF files with the expected standalone result; all input bytes are preserved.

The same runner rejects the unmodified reference compiler at the first unused
import with exit 3, while the corrected compiler succeeds. This is an observed
regression control, not an expected language rejection.

- Regression runner SHA-256: `270504497b489f00cd22c5c4dcd08dffe8d9dad8de08104e3050c4a16f59ce07`.

The normal ASDF test operation includes the runner. Full regression results and
the tested candidate are recorded in the associated pull request. This repair
does not by itself establish a replacement seed, the new compiler's native
profile, complete implementation acceptance or release.
