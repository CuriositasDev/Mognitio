# Repeated lifetime and file-resource observations

The portable runner binds the fixed input matrix, compiler and generated images,
retains heap/GC/fd observations, and leaves failed/unrun cells visible.
[Observations](v1.6.0-lifetime-observations.json) cover all 15 combinations:
bounded and retained histories at 10,000 / 100,000 / 1,000,000 iterations, and
success/read/decode I/O cases at 100 / 1,000 / 10,000 iterations.

All return expected exit 0 and empty streams. Bounded-history mapped bytes stay
at 1,069,056; collection counts increase from 2 to 17 to 168. The retained-history
control grows from 2,138,112 to 20,905,984 to 200,597,504 mapped bytes.
These are heap observations, not RSS or adopted memory-growth budgets.
I/O observations leave zero owned resources and at most four observed fds.

Six controlled runner scenarios check complete success, owned-resource leak,
fd leak, wrong exit, input mutation and timeout with partial output.
The real 15-case matrix and git diff --check pass. Compiler source is unchanged;
the normal language suite is not repeated for this test-only increment.

~~~sh
python3 tests/mgnc/v160-lifetime-harness.py
python3 tests/mgnc/v160-native-lifetime.py --compiler A --fixtures FIXTURES --output NEW_DIRECTORY
git diff --check
~~~

Formal wall/RSS and reclamation criteria remain separate adoption and acceptance
steps. The record does not establish whole-version acceptance.
