# Deterministic concrete procedure and descriptor order

Reversing actual concrete requests on one immutable semantic project produced
different ELF bytes even though execution agreed. Reordering an already
expanded plan did not test that condition.

Native planning now canonicalizes procedure instances by original body identity
and complete lexical bindings. Type arguments use structural identities rather
than interned TypeIds; value arguments preserve their constant or parameter
identity. Managed descriptors and list buffers use the same structural ordering.
An iterative merge sort bounds ordering cost. Runtime initializer order is
preserved while references are remapped.

The [record](v1.6.0-stable-concrete-order.json) identifies the tested source,
seed, source inventory, normal executable and observations.

## Validation

Two frozen fixtures vary actual requests without changing source bytes,
semantic input or runtime evaluation order. Both baseline artifacts differ;
both repaired pairs are byte-identical and execute successfully. The body-only
nested specialization also changes type-interning order. It covers lexical
type/value bindings that do not appear in the outer signature.

The independent whole IR, dataflow, concrete, closure, helper, native and root
checks pass, including 152 CFG graphs with 456 rejected mutations.
The generated runtime passes 90 observations. Eight review fixtures pass
16 normal/forced-GC observations. The 256-closure input builds in 118.79 seconds
with 209,387,520 bytes peak RSS and executes with its frozen status 15.
These are functional observations, not adopted performance budgets.
