# Mognitio 1.5.0 acceptance and release validation

All version 1.5 specification, design, Lisp and Mognitio implementation stages
were explicitly accepted on 2026-10-15, together with authorization to release.
The formal budget and complete measurement results are included in that acceptance.
This record defines the frozen identities and distribution gates; publication is
established by the signed assets attached to the immutable v1.5.0 release.

## Source gates

Run the complete normal-toolchain suite through the final 1.5 integration result.
Check the delivered checksum manifest and compare candidate and tagged source
archives with their exact tracked bytes, without Git metadata. Exercise documented
examples, language tests, ordinary builds and standalone execution.

Build mgnc from the archived release source with the accepted S2.
Require exact byte identity with accepted A before reusing its complete functional
and performance evidence. Re-run version-specific semantic/conformance and review
regressions, and the formal-record integrity audit. No package smoke test replaces
a compiler performance measurement.

## Frozen distribution gates

Follow the [distribution procedure](../packaging/README.md). Build one release-mode
normal toolchain from clean main with the locked Ubuntu image, SBCL, input core and
notice. Package that payload into one Debian package and one offline bundle.
Verify identical payload contents, identity, modes and ownership.

Only mgn and mognitio-lsp are installed. Neither distribution archive includes
mgnc, its source project or a launcher for it. The source archive includes the
experimental compiler for explicit builds.

Run protocol, analysis, boundary, projection, token, installer recovery/failure,
trust, signing and package-permission checks against the frozen payload.
Check actual 1.4.0 to 1.5.0 offline upgrades on Ubuntu 24.04 and 26.04, and the
unchanged consumer against the final normal compiler.

## Signing and publication

Create an immutable implementation tag directly identifying the verified main
commit, as required by the signing workflow. Freeze the draft assets and dispatch
production signing with the exact manifest digest. Download every signed draft
asset, compare frozen bytes and independently verify the production signature.
Run the package-acceptance workflow on both supported userlands, including
unrelated non-root execution after root installation, before publication.

Append the release to the APT registry through a reviewed pull request, retaining
all older releases. Verify production deployment and the public HTTPS repository
with signed-by on both supported userlands. Check upgrade, download hashes,
reinstall, removal, purge, LSP and standalone execution after removal.

## Evidence and boundaries

Retain exact candidate/main/tag commits, source archive identity, build identity,
artifact hashes, signing and package workflow results, APT deployment and execution
logs separately. Keep frozen artifacts and raw evidence in permanent release storage.

Only Linux amd64 with the documented Ubuntu userlands is in the package matrix;
namespace userland tests share the host kernel. The independently versioned
VS Code extension and consumer have separate release processes.
mgnc remains experimental and source-built. Complete semantic checking does not
establish whole-compiler self-rebuilding or native support for the full language.
