# Durable regression evidence recovery

This supplements the complete-backend acceptance after a restart removed
temporary raw logs. The historical acceptance summaries and receipt hashes
remain unchanged. [The fresh execution record](v1.6.0-evidence-recovery.json)
identifies this run separately; it does not claim to restore the lost files.

The reviewed baseline is 1760107644809f44e1530d1de8c1af60cf47d1a4.
The same 18,505,696-byte compiler A has SHA-256
d27ddf0ddc3b6105c508f92b10c8ea20903dfdf58193fadb0723d85190f380ff.
Ordinary compiler sources match the previous regression revision
4f2625dda8e94e0d5fddd9071ee193bba135e740. The fresh ordinary suite uses a
separate clean checkout of the reviewed baseline and the S10 development
runtime inputs. It builds a fresh development payload for analysis/LSP checks.

Fresh evidence covers:

- All 118 inherited semantic, 162 parse and 21 native-build performance cells,
  using the original frozen manifests and unchanged performance criteria.
- The complete ordinary Lisp suite and its downstream Python integrations.
- Packaged analysis, LSP, additional standard-surface analysis, diagnostic
  projection and semantic-token projection.
- All 182 ordinary-toolchain Levi observations and eleven observer controls.
- Complete C0/C1 check and lower plus 41 native generation/execution cases
  in each of the two minimal Ubuntu userlands.

Semantic performance uses one warm-up and three recorded runs. Parse/native
use one warm-up and five recorded runs. All performance stages run serially,
before the ordinary functional suites. An earlier native series using the
checked-in manifest is retained separately: its sources and expected results
are identical, but the manifest adds structural annotations. The authoritative
repeat uses the exact original manifest.

The userlands were downloaded again from the official Ubuntu Base archives
for 24.04.5 and 26.04.1. Archive checksums match their published SHA256SUMS.
Fresh prepared inventories, including empty bind-mount targets, are recorded.
They differ from the lost historical inventories; no claim of environment
byte-for-byte restoration is made. Inputs, compiler and criteria are unchanged,
and each isolated run checks that its own environment remains unchanged.

Preparation failures are retained too. Archive extraction was adjusted to
create regular files before absolute rootfs symlinks. The runtime was first
compared to the release-build lock; the correct reference for this development
acceptance is the immutable S10 payload identity. Its runtime, initial core
and copyright file all match. The first ordinary suite hit the Linux Unix-socket
pathname limit with a deep TMPDIR. A short persistent path fixed that issue,
but both persistent paths used ext4, bypassing the publication fault fixtures'
certified tmpfs profile. The original short /tmp tmpfs working environment was
restored while raw logs remained on persistent storage. Both failed attempts
remain retained. No production code or test oracle was relaxed.

Raw process streams, measurements, command/status logs, input manifests,
environment provenance and observer results are stored on persistent storage.
A separate raw-evidence inventory and archive bind the retained files.
Historical missing-log disclosure remains part of the original acceptance.
The already retained [103-cell formal series](v1.6.0-formal-performance.md)
and lifetime/reclamation results were not repeated or replaced.

This closes the reviewed evidence-retention gap. It changes no public contract,
accepted implementation strategy or budget. Release, tag and distribution
publication remain separate and have not been performed.
