# v1.5 wall-cutoff review correction

## Problem and correction

A delayed monitor could reap a normally exited child before reaching its deadline
check and leave the cutoff flag empty. The formal gate checked only the recorded
median and peak RSS, allowing a late warm-up or one late recorded run to pass.

The observer now compares its final elapsed time with the per-run cutoff on every
exit path. It preserves actual exit, signal, streams, timing and any earlier
failure reason; it never kills an already reaped child. A delayed observation is
not inferred to have completed within the deadline.
The formal gate independently requires a finite, nonnegative duration no greater
than the per-run cutoff for all four runs, including the warm-up. Only the three
recorded runs contribute to the median and maximum-RSS aggregate.

Corrected implementation: 93464b260366d0ee97a0be7c0ede4ac1aa26cc75.
Compiler source, A, accepted S2, fixed budget and original observations are unchanged.

## Regression evidence

The new v150-wall-cutoff.py runner has 45 checks. Against the previous helper
implementations it reports 15 failed checks; all 45 pass after correction.
Real subprocesses and real wait4 accounting exercise both the initial reap and
the RSS-unavailable exit-reap path, with delayed delivery of a completed child's
result. Exit 0 and captured output remain intact while the overrun is rejected.
Independent controls cover equality, each warm-up/recorded position, nonfinite,
negative, boolean and missing duration values.

The formal CLI harness now passes 56 checks, including warm-up and recorded-run
overruns with an absent cutoff flag. Both correctly return failure even when the
recorded median remains within budget. The existing monitor harness also passes.
[Before](v1.5.0-wall-cutoff/before.json), [after](v1.5.0-wall-cutoff/after.json),
and [source bindings](v1.5.0-wall-cutoff/source.json) retain the reproduction.
