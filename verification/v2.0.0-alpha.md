## Checks on this candidate

| Check | Observed result |

| [Cross-version and isolation tests](../tests/mgnc/v200-alpha-bootstrap.py) | 133 CLI/ELF observations across the seed and alpha. The isolated alpha payload completed run, build, test and project LSP. A standalone ELF executed in a separate root without the compiler. |

| [Native arithmetic oracle](../tests/mgnc/integer-runtime.py) | The 1.9.0 seed and Compiler A each produced code matching 39,510 independent arithmetic and projection checks. |
| [Constant pool oracle](../tests/mgnc/v200-integer-pool.py) | Repeated constants shared data. Both toolchains passed 22 chunk vectors and 10 mutation controls for operand encoding, constructor targets, distinct canonical values and malformed pool data. |

A sample with a 4,096-digit literal completed static checking in
0.10 s, normal build in 0.48 s and project LSP
analysis including startup in 0.42 s.
The measured build peak was 46,560 KiB. These are single-run
measurements on Linux amd64. [GC checks](../tests/mgnc/v200-alpha-reclamation.py)
compared 64 and 4,096 iterations with the same final roots. Allocations rose
from 197 to 12,293 and live memory after collection was 184 bytes in both runs.
See the [candidate GC measurements](v200-alpha-gc.json) and the
[independent native GC check](v200-alpha-gc-native.json).

The [scaling test](../tests/mgnc/v200-alpha-scale.py) measures elapsed time and
peak process RSS for check, lower, build and project LSP. It varies literal size,
reference count and the number of distinct template value arguments. LSP timing
and peak RSS include startup, the protocol driver and child processes.

Fifteen existing example projects matched the 1.9.0 exit code, stdout and
stderr both in alpha run and in standalone executables. The two annotated
tests in the testing example also matched the seed.

Compiler A also checked its entire input compiler project successfully.
