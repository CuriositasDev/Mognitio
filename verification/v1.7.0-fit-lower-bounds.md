# Reusing valid first-fit search bounds

Whole-compiler encoding repeatedly requests different allocation sizes. An
exact-size cursor miss previously restarted from the free-list head even when
the selected set retained a cursor for a smaller request.

On a miss, the allocator may reuse the first way's cursor when that owner's
size is below the new request, or the second way's admissible cursor otherwise.
Every skipped block was too small for the earlier request and therefore cannot
fit the larger one. An owner above the requested size never supplies a bound.
The new search still selects the first fitting block in original list order.

Owner/cursor pairs move together. Existing link repair and collection resets
continue to invalidate or redirect bounds. Slot count, context layout, physical
allocation, heap geometry, reserve policy, collection timing and mapping-failure
behavior retain their existing contracts.

The [allocator oracle](../tests/v160-fit-cursors.lisp) interprets actual emitted
instructions and compares every result and the complete remaining free chain
with an independent ordered-block model. Increasing/decreasing requests,
collisions, eviction, splits, consumed owners and collection resets are covered.
Two reversed-direction mutations must fail first-fit equivalence; existing owner
and pair mutations remain independently identified.

A 2,048-block prefix followed by 492 distinct increasing requests requires at
most 33,276 visits: sixteen cold set scans plus one visit per request. Disabling
cursor reuse preserves values but exceeds that bound. This structural-work
check is not a formal wall-time or RSS budget.

Full native regression and source-generated compiler regression remain required.
A new immutable seed must be frozen and qualified before dependent compiler
generations can serve as bootstrap acceptance evidence. Earlier seed bundles
remain unchanged; this increment does not declare final version acceptance.
