# Two-way exact-size allocator cursors

Large native allocation requests share 32 cursor slots. A direct-mapped slot
discarded its known first-fit prefix whenever another size collided with it.
Alternating colliding requests could repeatedly walk the complete prefix.

The runtime now uses 16 two-way sets in the same storage. Each way owns an
exact size and a free-list-link cursor. A second-way hit promotes the complete
pair; a miss replaces the least recently used pair and initializes its cursor.
The [implementation](../src/native-memory.lisp) preserves first-fit selection,
block splitting, cursor-owner repair and collection invalidation. Heap geometry,
reserve/growth caps, context layout and allocation failure behavior are unchanged.

## Independent validation

The [allocator regression suite](../tests/v160-fit-cursors.lisp) interprets the
actual emitted operations. An independent ordered-block model selects the first
fitting block and verifies the complete remaining free chain after every request.

- 576 cases / 4,608 requests cover zero through 2,048 prefix blocks, mixed sizes,
  promotions, eviction, smaller colliding requests, owner removal and cursor reset.
- Two cold scans suffice for two alternating colliding sizes. Later hits must
  avoid the unchanged prefix; forcing every lookup to restart preserves values
  but fails this operational bound.
- Wrong first-way ownership, wrong second-way ownership and moving only half of
  a promoted pair must fail independent first-fit checks. Mutation membership is
  checked before entering the expected rejection boundary.
- Existing native pointer, lifetime, reserve, exact first-fit and collection
  regressions remain required, alongside the complete compiler integration suite.

These are correctness and structural-work checks. They do not adopt wall-time
or RSS budgets or establish a causal speed claim from concurrent diagnostics.

## Bootstrap boundary

The [preceding qualified seed](v1.7.0-seed-arena-index.md) remains immutable.
A new seed must be built from the accepted repair source, verified component by
component, restored in isolation, and requalified for the complete compiler
corpus before any new dependent image is accepted. Source-built host diagnostics
and binary-patched diagnostic images are separate from qualified S / A / B images.
Whole-compiler generation, consumer/regression acceptance and formal performance
measurements remain separate gates. This repair is not a version acceptance or
release record.
