# Static-root range rejection

Generated native garbage collection searched both static-root tables for every
candidate pointer, including heap addresses beyond the last static entry.

The Lisp backend now rejects addresses outside each static-root table's first
and last starts before its existing exact-membership search. Endpoints and holes
still use that search; candidates are never dereferenced. Empty and singleton
tables keep their previous path. Descriptor lookup is unchanged.

The Mognitio backend already has this range rejection. Its 296 compiler files,
including 293 Mognitio sources, are unchanged by this correction.

## Validation

The focused tests cover empty, singleton and larger tables, exact endpoints,
interior holes, unsigned high addresses, comparison bounds, and three faulty
branch mutations. They passed 72,478 assertions and one native process.

The code/test commit `5b7192073f530a6af1c604795fa161b0bf47e35e` passed
`sbcl --noinform --script scripts/test.lisp`: 262 Lisp tests, 17,018,030
assertions, 1,371 processes, and all 29 Python suites, with zero failures.
Independent raw review confirmed the result and complete process cleanup.

A fixed diagnostic comparison retained a warmup and all three measured starts
per variant. The median full-source lowering time changed from 238.33 to 216.43
seconds; the width-64 method build changed from 20.15 to 18.28 seconds. The
corrected compiler's measured maximum RSS was 1,281,884,160 and 64,049,152 bytes,
respectively. These are diagnostic observations, not whole-version acceptance.

This source acceptance does not establish fresh seed qualification or complete
version performance acceptance. A changed bootstrap implementation requires a
new immutable seed and candidate, with fresh dependent acceptance.
